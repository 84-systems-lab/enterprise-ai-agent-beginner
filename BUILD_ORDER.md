# One progressive build route

| Chapter | Capability | Result to inspect |
|---|---|---|
| 1 | A Question and Your First Program | Save, run and change hello.py; repair the deliberate NameError. |
| 2 | Teach a Small Program to Read | Read the policy, find matching lines and explain a no-match result. |
| 3 | From Search Results to Supported Answers | Keep evidence and source locations together; check each answer claim. |
| 4 | Give the Program a Tool | Create your own small loop entry point; inspect a real local MCP read. |
| 5 | A Browser, an API and a Signed-In User | Inspect browser/API JSON and prepare separate API/browser identities. |
| 6 | Give the Application a Cloud Home | Verify the owned account, model and reviewed infrastructure deployment. |
| 7 | Build the Shared Knowledge Store | Extract, create schema, upload, retrieve and inspect the first supported answer. |
| 8 | Keep Knowledge and Work Reliable | Update and retire only the experiment; inspect owned background jobs. |
| 9 | Read Live Documents as the User | Compare allowed and denied live document access as two users. |
| 10 | Connect Business Records through MCP | Read the known Case through the connected user; test denial and reconnect. |
| 11 | Build the Application Agent | Compose the live agent and compare selected sources, activity and evidence. |
| 12 | Prove, Operate and Improve the System | Demonstrate supported facts and controlled failures; record recovery and cleanup. |

Chapters 1-4 run locally without a cloud account or paid model request.
Chapter 5 prepares identity before Chapter 6 exposes the API. Chapter 7 performs
schema -> upload -> retrieval -> answer in order; no forward/backward build jump.
Chapter 4 uses a real local MCP read and a scripted model. The live model and
provider checks are later, distinct checkpoints.
